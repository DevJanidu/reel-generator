# ODD FRAME station lifecycle

The existing React dashboard/FastAPI controller runs at http://127.0.0.1:8123. Launch scripts/start.ps1 so the browser receives its controller capability. SQLite is the trusted controller's index/settings store. Authoritative state/history lives in each production_status.json; native workers never open the shared database.

1. Startup initializes/migrates the index, displays skills/provider/tool status, cleans interrupted private job homes and requeues interrupted deterministic renders. Interrupted AI requests require explicit retry; account usage is not silently replayed.
2. Create New Reel snapshots all four full skills, master/rules and stage prompts into a unique idea-session workspace. Every call sends their complete validated content. Codex CLI is preferred when authenticated and MXC passes. Authorized Claude bare mode and explicit API mode are alternatives; manual exports the identical request/schema.
3. Selecting a story atomically allocates OF_RNNN and an independent directory, pinning creative inputs, small Remotion templates/dependency records and configured signature music. The automatic dashboard provider queues script creation; custom premises may skip ideation.
4. Writing and internal retention review use the same pinned identity. The UI shows actual progress/errors/cancel/retry. Models return structured content and do not edit files. Same-episode conflicts are rejected/serialized. Independent AI jobs may run up to the configured limit only after per-workspace verification; default one. Rendering remains one at a time.
5. APPROVE SCRIPT & CONTINUE records exact narration/hash/version, timestamp and auto-export authorization. Preparation runs automatically without further artifact approvals.
6. Schema/coverage validation precedes compilation of characters, continuity, provisional storyboard/timeline, retention/style locks, asset manifest, self-contained image-only Flow prompts/batches, captions, music direction and publishing draft. Only real complete output becomes AWAITING_ASSETS.
7. Import scene-ID stills, narration, trustworthy 1-4-word SRT split at scene boundaries, and one instrumental if no shared signature was configured. Upload spools and all files are episode-local. Record rights evidence. Validated music is pinned; later global changes cannot replace it.
8. Refresh/background scanning invokes native-isolated decode/ratio/duration/SRT/coverage checks. Missing assets and timing ambiguity are actionable blockers, never invented precision. Valid assets automatically queue editing.
9. The isolated draft worker builds the measured timeline, normalizes/ducks/balances audio, caches decoded waveform peaks and marks EDIT_READY. No MP4 is rendered. Open `/episodes/<numeric-id>/editor` to review the populated four tracks with the actual Remotion composition. Changes autosave locally with revision conflict detection and historical revisions. Static stills, pinned-profile transitions, animated center typography, exactly two audio sources, no SFX.
10. Render Final Video queues the exact saved revision under the existing script authorization. Preview/QC, final render/mastering, full decode/FFprobe and authorization/input-hash rechecks precede a versioned export. No additional script approval or publishing. Failures retain local diagnostics; revocation blocks final commitment. Historical snapshots and exports remain intact.

AI Activity is available across the dashboard and Live Editor. Its SSE stream replays episode-local sequenced events on reconnect. Provider messages are allowlisted status metadata; hidden reasoning and raw CLI transcripts are excluded. Frame progress comes from Remotion callbacks; AI generation uses descriptive stages without invented percentages. See STUDIO_UPGRADE.md for verification and limitations.

Reports distinguish machine checks from artistic judgment, acoustic sync, rights and listening. Analytics records actual owner-supplied data only. Suggestions for shared improvements go into episode reports; only a separate explicit development operation updates shared files. See SECURITY.md and AI_PROVIDERS.md.
